# Canonical Artifact Schemas

Frozen contracts for the Person 3 (ML / Validation / Models & Decision) artifacts.
These are the contracts named by the master directive roadmap and are what the code
in `src/` and the tests in `tests/` actually implement.

Conventions used by every artifact:

- **Identifiers are strings, always.** `S1-…`, `S2-…`, `S3-…` ids are never cast to a
  numeric dtype. A leading zero or a country prefix would silently corrupt a numeric cast.
- **`pair_key`** is `s1_id + "::" + candidate_id` and is the join key between candidates,
  labels, features, and scores.
- **Row counts are preserved exactly.** Labeling and scoring never drop, merge, or invent
  candidate rows. Output row count must equal input candidate row count.
- Artifacts are Parquet unless stated otherwise.

---

## 1. `artifacts/folds.parquet` (Phase 1)

Frozen entity-level 5-fold assignment. Generated by `scripts/generate_folds.py` with
`n_folds=5, random_state=42`.

| column    | type    | description                                                        |
| --------- | ------- | ------------------------------------------------------------------ |
| `s1_id`   | string  | S1 entity identifier                                               |
| `fold_id` | int8    | Fold index in `[0, 5)`; every S1 entity appears exactly once       |

Invariants:

- Exactly 5 distinct `fold_id` values, every fold non-empty.
- The `s1_id` set is exactly the set of `entity_id` values in
  `dataset/train/train_source1.tsv` — no missing rows, no extra rows, no duplicates.
- Candidate pairs inherit their S1 entity's `fold_id`, so no entity is ever split
  across folds and no fold leakage is possible.
- Stratification key is `(country, has_match, match_count_bucket)` at the S1 entity
  level, where `has_match` is `match_count > 0` and `match_count_bucket` is
  `0` (zero matches), `1`, `2-3` or `4+`.

Reference fold sizes on the real training data (2,206,821 S1 entities):

| fold | entities  | share |
| ---- | --------- | ----- |
| 0    | 441,365   | 20.00% |
| 1    | 441,364   | 20.00% |
| 2    | 441,364   | 20.00% |
| 3    | 441,364   | 20.00% |
| 4    | 441,364   | 20.00% |

## 2. `artifacts/candidates.parquet` (Phase 1 / Person 1, upstream)

Candidate pairs per S1 entity. P1 owns production of this file; Person 3 consumes it.

| column             | type   | description                                        |
| ------------------ | ------ | -------------------------------------------------- |
| `pair_key`         | string | `s1_id + "::" + candidate_id`                      |
| `s1_id`            | string | S1 entity identifier                               |
| `candidate_id`     | string | `S2-…` or `S3-…` entity identifier                 |
| `candidate_source` | string | `"S2"` or `"S3"`                                   |
| `n_routes`         | int8   | Number of retrieval routes that produced this pair |
| `best_rank`        | int16  | Best retrieval rank across routes                  |
| `best_score`       | float32| Best retrieval score across routes                 |

Ground truth is joined to this file to derive labels. The ground-truth TSV is **wide**:
one row per S1 entity with a comma-separated `matched_entity_ids` field, where an empty
field means a true singleton. It is not a long one-row-per-pair file.

---

## 3. `artifacts/train_labels.parquet` (Phase 2)

Binary training labels for candidate pairs. Produced by
`src/models/labels.py::build_train_labels`.

| column    | type   | description                                            |
| --------- | ------ | ------------------------------------------------------ |
| `pair_key`| string | `s1_id + "::" + candidate_id`                          |
| `y`       | int8   | `1` if the pair is a true match, else `0`              |

Invariants:

- `y == 1` iff `candidate_id` is in the ground-truth match set for that `s1_id`.
- Row count equals the candidate row count exactly — zero hallucinated rows, zero
  dropped rows. Unmatched retrieved candidates become hard negatives (`y == 0`).
- `y` has no missing values.

---

## 4. `artifacts/features.parquet` (Person 2, upstream)

Model input rows, one per candidate pair. P2 owns production; Person 3 consumes it.
The key/model columns for P3 are:

Identifiers and retrieval:

`pair_key`, `s1_id`, `candidate_id`, `candidate_source`, `n_routes`, `best_rank`,
`best_score`, plus per-route rank/score pairs `exact_name_{rank,score}`,
`numeric_{rank,score}`, `rare_token_{rank,score}`, `tfidf_name_{rank,score}`,
`tfidf_addr_{rank,score}` (NaN when the route did not retrieve the pair).

Name features: `name_char_cos`, `name_token_set`, `name_token_sort`,
`name_contain_idf`, `name_exact_conservative`, `name_exact_aggressive`,
`name_len_diff`, `name_token_count_diff`.

Address features: `addr_char_cos`, `addr_contain_idf`, `addr_numeric_jaccard`,
`addr_numeric_conflict`, `addr_len_diff`.

Country: `country_eq` only — `1.0` equal, `0.0` unequal, `NaN` missing. No identity
one-hots, and country is an input feature rather than an assumption about the universe.

Missingness: `s1_name_missing`, `cand_name_missing`, `s1_addr_missing`,
`cand_addr_missing`. NaN-safe and never zero-filled, because a blank address can still
be a true match.

Monotonic-similarity columns (the constrained direction, all higher-is-better):
`name_char_cos`, `name_token_set`, `name_token_sort`, `name_contain_idf`,
`addr_char_cos`, `addr_contain_idf`, `addr_numeric_jaccard`, `best_score`.

## 5. `artifacts/scores.parquet` (Phase 5)

Out-of-fold and final model scores. Produced by `src/models/train_cv.py::train_cv`.

| column         | type    | description                                          |
| -------------- | ------- | ---------------------------------------------------- |
| `pair_key`     | string  | `s1_id + "::" + candidate_id`                        |
| `s1_id`        | string  | S1 entity identifier                                 |
| `candidate_id` | string  | candidate entity identifier                          |
| `p_raw`        | float32 | Raw model probability                                |
| `p_cal`        | float32 | Calibrated probability (currently equal to `p_raw`)  |
| `fold_id`      | int8    | Fold the score was produced by                       |
| `is_oof`       | bool    | `True` for out-of-fold rows                           |
| `model_version`| string  | Model identifier, e.g. `logreg_v1`, `lgbm_v1`        |

Invariants:

- Exactly one OOF row per candidate pair.
- The model producing fold `k`'s scores is never trained on fold `k`.
- Row count equals the candidate row count.

## 6. `artifacts/decision_config.json` (Phase 6)

Frozen decision parameters tuned strictly on OOF scores.

```json
{
  "t_global": 0.5,
  "t1": 0.5,
  "t2": 0.5,
  "model_version": "logreg_v1",
  "enable_reverse_consistency": false,
  "n_oof_rows": 0,
  "tuned_on": "oof"
}
```

`T1` is the entry threshold applied to a candidate's score when it is the first
candidate considered for an S1 entity. `T2` is the continuation threshold for
subsequent candidates. Both are tuned to maximize macro-F0.5 on OOF predictions only.

---

## 7. Evaluation contract (`src/validation/metrics.py`)

`macro_f05(ground_truth, predictions)` averages a per-entity F0.5 over **every** S1
entity, including zero-match entities.

- `|T_i| == 0` and `|P_i| == 0` → score `1.0` (correct abstention)
- `|T_i| == 0` and `|P_i| > 0`  → score `0.0` (false match on a singleton)
- `|T_i| > 0` and `|P_i| == 0`  → score `0.0` (missed all true matches)
- otherwise `F0.5 = 1.25 * P * R / (0.25 * P + R)` with `P = |P_i ∩ T_i| / |P_i|` and
  `R = |P_i ∩ T_i| / |T_i|`

Predictions are deduplicated sets, so repeated ids cannot inflate a score. The
predict-nothing baseline (all empty predictions) scores `0.0558`, since only the
123,247 zero-match entities of 2,206,821 score `1.0`. Any pipeline result must be
compared against that floor, not against `0.0`.
